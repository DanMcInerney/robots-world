# Robots World principles

Robots World tests control software against a changing environment. The goal is a small, reusable experiment platform whose results are inspectable and whose conclusions survive a change of robot, controller library or simulator.

1. **The world continues.** Physics, sensor acquisition, communication and local actuator loops run independently of model inference. A slow decision never silently pauses the experiment.
2. **One simple boundary.** A controller receives explicitly assigned `RobotPort` instances. Robots advertise their commands, sensors and communication capabilities. Models, sensors, physics and transports are replaceable modules, without a mandatory agent framework.
3. **Evidence has an owner and a time.** Controllers see their acquired sensor data and delivered messages. Evaluators may inspect truth; they cannot feed it back into a controller. Acquisition, receipt, observation delivery and action application remain separate timestamps. Refreshing an envelope does not refresh its contents.
4. **Keep fast work local.** Deterministic servos, guards, ordered jobs and permitted routines continue between model calls. Use ordinary code for known rules and computation. A small model can select a bounded behavior; a general agent can plan, author routines and handle new situations. Every layer must earn its latency and cost.
5. **Actions have lifetimes.** One revocable owner writes each robot. Admission is distinct from completion. Commands and messages have identities and expiry; cancellation and stale replies cannot revive old authority. Uncertain effects are reconciled rather than silently replayed.
6. **Communication is part of the experiment.** Queue admission, delivery, acknowledgement and agreement are different events. Independent robots learn about peers through their configured sensors and actual communication channels. A shared agent with several ports is explicitly centralized control.
7. **Compare complete, capable systems fairly.** Give competing controllers the same task, sensors, plant, local guards, candidate actions and resource constraints unless the changed component is the experiment. Preserve route and routine capabilities when comparing complete native agents. Declare restrictions when testing only one layer. Use deterministic fixtures to validate mechanics; include scripted competitors only when they answer the experimental question. A supplied skill or candidate generator must not secretly solve the mission. Injected delays test architecture; actual model runs measure model performance.
8. **Record enough to challenge the result.** Save exact configurations, source/model versions, seeds, observations, decisions, command outcomes, sensor ages, timing, radio stages, costs when available and trace coverage. Report failures and discarded data. Separate warm execution from startup and code-authoring cost.
9. **Portability is a contract, qualification is evidence.** Reusing a port or wire protocol does not prove physical fidelity, hard real-time behavior or hardware readiness. Unsupported backend capabilities fail explicitly. State which dynamics, devices, native harness behavior and transport paths were actually tested.
10. **Preprocessing may measure, not invent evidence.** Sensor simulators may read truth to synthesize physical measurements. Perception and derived features receive only those measurements and declared calibration. They cannot use hidden depth, identity, future motion or evaluator scores to fill uncertainty, reject ambiguous readings perfectly or select a mission action. Preserve the raw input and state every physical assumption, including known markers, navigation estimates and local flight controllers.

See [design](docs/design.md), [experiments](docs/experiments.md), and the [DroneRTS comparison contract](docs/dronerts-comparison.md). These principles guide new experiments; they do not declare every proposed integration implemented.
