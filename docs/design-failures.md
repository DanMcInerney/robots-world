# Design failures and experiment decisions

Append findings; preserve unsuccessful runs and frozen sources. Evidence below is local, ignored runtime data, not committed inference evidence. A hypothesis is not a demonstrated cause. Each change must name its comparison and sensor provenance.

## 2026-09-18 · F01: marker-only observations caused blind hovering

- **Observed:** 1,436/1,436 zero-translation choices; one marker detection in 1,419 distinct frames. Separate actuator checks moved about 1.01 m in 2 s per axis at 0.6 m/s.
- **Evidence:** [.runtime/sensor-hover-diagnosis.json](../.runtime/sensor-hover-diagnosis.json), [sensor-motion-mechanics.json](../.runtime/sensor-motion-mechanics.json), [camera representation review](jev-camera-representation.md).
- **Decision:** use actual recorded RGB, broad colour regions and an image-framing goal. Drop rangefinder and unavailable metric/global navigation requirements. Mechanical scripts qualify actuation; they are not policy competitors.

## 2026-09-18 · F02: readable observations did not produce good closed-loop control

- **Observed:** all 15 pixel flights failed sustained following; all moved (1.6–28.9 m). Conditional target selection was correct 54/54 times when blue was detected. Narrow posthoc questions were correct 60/60 times on ten saved development observations, not independent flights.
- **Evidence:** [held-out report](../.runtime/experiments/jev-pixels-held-out-v2/report.json), [analysis](../.runtime/experiments/jev-pixels-held-out-v2/analysis.json), [diagnostics](../.runtime/experiments/jev-pixels-development-v1/posthoc-diagnostics.json), [results](jev-pixels-results.md).
- **Interpretation:** missing range does not explain wrong-direction camera turns. Broad action questions, coupled controls, stale angles and missing feedback are plausible causes; none is isolated yet.
- **Decision/test:** keep the same full 43,218 commands and camera. Compare the original words baseline with semantic menus, then add compact temporal evidence, then pair XY and camera axes. Each comparison adds one declared factor. No scripted aiming or choice pruning.

## 2026-09-18 · F03: exact replay confused JSON zero with signed zero

- **Observed:** audit stopped after a completed flight because reconstructed `-0` differed from JSON `0`; a second occurrence affected pitch. Inference was retained, not repeated to seek a better result.
- **Evidence:** [first retained flight](../.runtime/experiments/jev-pixels-held-out-v1/recovered-report.json), [audit amendments](../.runtime/experiments/jev-pixels-held-out-v2/report.json), [methods](jev-pixels.md).
- **Fix:** normalize every reconstructed request/action to JSON semantics. Record auditor-only source amendments and recover from original traces. Regression-test zero in request, command and replay.

## 2026-09-18 · F04: scoring included an unobserved global boundary

- **Observed:** composite success requires global bounds, but the RGB-only controller receives neither position nor altitude. This did not explain zero sustained framing.
- **Evidence:** [scoring contract](jev-pixels.md), [next-loop review](jev-loop-next.md).
- **Decision:** retain old composite results for comparability; report framing and safety violations separately. Do not claim boundary compliance is an observable camera-only task.

## 2026-09-18 · F05: absent tracks and command receipts left gaps in feedback

- **Observed:** the old formatter discards a missing region immediately; history is uncompressed samples. Receipts acknowledge command admission, not application or achieved velocity. World application logs are private evaluation evidence.
- **Evidence:** [tracker](../src/perception/color-tracks.ts), [controller](../experiments/jev-pixels/controller.ts), [review](jev-loop-next.md).
- **Decision/test:** derive image-plane rates and bounded last-seen records only from delivered observations; display their acquisition ages and measured camera-angle change. No extrapolated world position, range, true velocity or private application events. Pairing controls is a separate subsequent arm. Optical flow/VIO and a body-rate interface remain later experiments, not bundled into this test.
- **Status:** implementation and real-inference outcomes will be appended below.

## 2026-09-18 · F06: semantic menus and history did not fix the development flight

- **Observed:** four 20 s development flights (seed 82), 279 real decisions and 388 audited images. All failed sustained framing. Target detection fractions A/B/C/D were 6.8% / 22.9% / 23.2% / 13.8%. All used identical target/crossing trajectories. The paired arm consumed 468,822 tokens versus baseline 167,491.
- **Evidence:** [development report](../.runtime/experiments/jev-loop-development-v1/report.json), [analysis and concrete wrong-direction examples](../.runtime/experiments/jev-loop-development-v1/analysis.json), [predeclared method](jev-loop-experiments.md).
- **Interpretation:** better retention in one scene is insufficient evidence of improvement. Pairing more choices increases cost without guaranteed coherence. Image rates and missing-track memory are present, but their usefulness is unproven.
- **Decision:** keep all four arms and freeze the source unchanged for the twelve predeclared held-out flights. Do not select a successful-looking subset or add unavailable range/velocity to rescue this run.
- **Additional diagnosis, separate from flights:** after the batch, ask original versus direct camera-aiming questions on the earliest and last blue-visible observation per development arm, retaining the full 9/7 or 63-option angle menus. This tests question scope without pruning choices; the direct question explicitly assumes no translation/object motion. No answers will be applied, and no held-out controls will be tuned. [Diagnostic method](../.runtime/jev-loop-diagnostics.mjs).

## 2026-09-18 · F07: more history and larger paired menus still failed held-out following

- **Observed:** 0/12 passes and 0% fully framed time after warmup in every arm. A/B/C/D mean target detection: **5.2% / 11.6% / 13.4% / 11.3%**; input tokens: **0.959M / 1.141M / 1.271M / 3.015M**. Pairing cost 2.37× the same-state independent C arm, with lower target retention. No controller errors; all 1,710 completed decisions and 2,364 acquired images passed reconstruction audits. Matched target/crossing trajectories were identical; maximum simulation lag was 151 ms.
- **Evidence:** [visual report](http://127.0.0.1:8870/pixels.html?report=/.runtime/experiments/jev-loop-held-out-v1/report.json), [aggregate and concrete decisions](../.runtime/experiments/jev-loop-held-out-v1/analysis.json), [frozen source index](../.runtime/experiments/jev-loop-held-out-v1/source/SNAPSHOT.json). The original trials and scores are retained.
- **Diagnosis:** on eight saved development observations, direct aiming wording selected a turn toward the current image bearing on **8/16 axes**, versus **2/16** for original wording. Menus and state were identical; four cases share the initial view. This no-motion diagnostic is not flight accuracy. [Exact requests/probabilities](../.runtime/experiments/jev-loop-development-v1/full-menu-diagnostics.json), [counts](../.runtime/experiments/jev-loop-development-v1/full-menu-diagnostics-analysis.json).
- **Decision:** retain these as experiment variants, not a recommended controller. Do not add range merely to explain elementary turn-direction failures. Next test: separate **direction** from **magnitude**, both chosen by Jev, instead of merging more controls into a larger Choice. Eleven questions (two per signed axis plus FOV), or sixteen with conditional magnitudes, can preserve the same actuator set. Code would only map the selected values; no servo recommendation in state. Use fresh held-out seeds. **Proposed, not implemented or tested.**
- **Basis:** the [official Choice contract](https://docs.typesafe.ai/primitives/choice) confirms full option sets and independent questions; [Jev's limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13) warn about numeric precision, indirection and multiple judgments in one question. These support the next comparison; they do not establish its result.

## 2026-09-18 · F08: temporal evidence is sparse and colour perception is incomplete

- **Observed:** C included a usable image rate for at least one region in only **64/435** completed decisions, and historical missing regions in **156/435**. Rates are deliberately unknown across clipping, gaps and zoom changes. Dark/grey surfaces never become colour regions. The controller lacks achieved velocity and observed application status.
- **Evidence:** [availability counts](../.runtime/experiments/jev-loop-held-out-v1/analysis.json), [sensor limitations](jev-loop-experiments.md), [measurement-only adapter](../src/perception/image-motion.ts).
- **Next separate test:** qualify a goal-independent tracker on saved RGB sequences before more paid flights: correspondence loss, motion noise, occlusion, grayscale coverage and runtime. OpenCV feature flow is a candidate, not yet installed or benchmarked here. Preserve acquisition-side history even when inference misses frames; measure whether this adds useful evidence. Never equate image flow with metres/second, clear space or true depth. This round added no world-core features or mandatory vision dependencies.

## 2026-09-18 · F09: decisions precede observable effects of the preceding command

- **Observed:** latest batch: 1,662/1,662 decisions with an applied preceding command use an image acquired before that application; another 36 follow commands never applied. Typical request interval is 260 ms, but image-to-application median is 580 ms in every arm. The older 15-flight pixel batch has the same pattern: 2,071/2,071 and 580 ms. This is delayed feedback, not absence of all feedback; older commands can affect subsequent images.
- **Evidence:** [latest deep audit](../.runtime/experiments/jev-loop-held-out-v1/deep-audit.json), [older feedback audit](../.runtime/experiments/jev-pixels-held-out-v2/feedback-audit.json), [detailed diagnosis](jev-loop-diagnosis.md). All 1,666 latest first-application records also have accepted MAVLink adapter receipts.
- **Interpretation:** untimestamped recent admission receipts do not establish which commands an image reflects. Faster requests alone do not fix that causal gap. Nervelet or a slow native agent is not involved in these direct-API flights.
- **Next test:** compare an explicitly application-aware loop with the current streaming loop, using declared device telemetry and acquired timestamps. Keep physics/acquisition continuous. Never feed private evaluator events to Jev; missing hardware acknowledgements remain unknown. No loop change or new paid inference in this audit.

## 2026-09-18 · F10: “keep” resets an absolute setpoint to an old measurement

- **Observed:** `pixelAction` maps zero yaw/pitch to the delivered image's measured angles. An offline mechanical reproduction turned from -135° to -103°, then a zero yaw increment sent -134.7° and turned back to -128.4°. This follows the written dated-angle contract but contradicts the ordinary meaning of the option label “keep heading.” It can undo an ongoing adjustment.
- **Evidence:** [mechanical result](../.runtime/experiments/jev-loop-held-out-v1/keep-heading-diagnostic.json), [reproduction](../.runtime/jev-keep-heading-diagnostic.ts), [mapping](../experiments/jev-pixels/controller.ts). This is an actuator-contract test, not inference or a scripted mission competitor. Flight angle estimates in the deep audit use the preceding 100 ms trajectory sample and are labelled approximate.
- **Next test:** choose and document one meaning: retain the previous absolute setpoint, stop turning, or send an explicit rate. Qualify zero/nonzero controls through delayed/repeated packets before more prompt variants. These alternatives change the contract and must be evaluated separately; none is silently substituted into old flights.

## 2026-09-18 · F11: elementary direction errors precede target loss

- **Observed:** every initial view contains blue left and below centre. First yaw choice moves the camera away from its image bearing in 10/12 flights; first pitch choice does so in 11/12. Target first disappears at 2.18–7.08 s; 8/12 never see it again. Blue is absent in 1,528/1,710 consumed decision images, and the formatter returns no colour regions at all in 1,120/1,710. Missing range cannot explain initial camera-direction errors. Camera-axis signs alone are not a complete coordinated-action score.
- **Evidence:** [initial decisions, timelines and totals](../.runtime/experiments/jev-loop-held-out-v1/deep-audit.json), [first RGB image](../.runtime/experiments/jev-loop-held-out-v1/frames/loop-temporal-1301/camera-200.png). For C, a blue motion rate exists in 37/59 blue-visible decisions (63%): F08's 64/435 any-region rate also reflects time spent blind, not just tracking failure.
- **Interpretation:** current questions combine object selection, inverse image motion, magnitude and coordination. Jev's [documented limits](https://docs.typesafe.ai/model-jaggedness/jev-1.13) make this a poor unqualified policy interface. Low confidence accompanies visible-target camera decisions; confidence measures distribution concentration, not demonstrated flight safety. Initial positions are not balanced across image quadrants.
- **Next test:** qualify direction, magnitude and target selection separately on balanced development images, then frozen fresh images and camera-only physical loops before enabling all axes and recovery. Keep full menus in end-to-end arms. Merely summing existing probabilities by direction seldom reverses wrong top choices; F07's factorization is a hypothesis, not a demonstrated fix.

## 2026-09-18 · F12: representation improvements must preserve who makes the decision

- **Observed:** colour regions omit grey/dark obstacles; image rates mix camera rotation, translation and target motion; recent receipts omit observed execution and velocity. Paired menus cost 2.37× C without sustained following. No option-cap failure occurred: at most 63 choices per question. The real API, pixel-only reconstruction and actuator transport work; this does not qualify the policy or cheap-board performance.
- **Evidence:** [colour filter](../src/perception/color-tracks.ts), [motion formatter](../src/perception/image-motion.ts), [method/results](jev-loop-experiments.md), [Choice contract](https://docs.typesafe.ai/primitives/choice).
- **Next test:** compare compact calibrated image coordinates, named measurement bins, acquisition-side tracking and camera-rotation compensation as separately declared sensor transformations. Preserve unknown depth, ambiguity and image age. Arithmetic may derive evidence; `target left → turn left`, target-following controllers and collision recommendations are policy assistance and require labelled ablations. Jev must still choose actual control direction/magnitude in the direct-control arm. A classical visual-servo hybrid is a separate legitimate architecture, not evidence that Jev performed its servo calculations.

## 2026-09-21 · F78: the find-and-follow ladder (planned before inference)

- **Reason:** F77 established that no prior closed-loop evidence used the real sensor's latency, that the working per-option-consequence encoding has never been tested against a search/obstacle fixture, and that no rung has ever had a capable reference controller. The owner separately asked for a staged test ladder built with Robots World, reviewing and editing Codex's existing test designs rather than discarding them, that starts simple (track when visible; find when facing the wrong way; find from long distance) and ends at the hardest case (car out of sight at start, in an obstacle scene, scout then follow).
- **Design:** [`docs/jev-find-follow-ladder.md`](jev-find-follow-ladder.md) — L0 through L9 plus prerequisite sub-rungs (L3a/L3b, L5-pre, L9-pre). L0 is gates only (zero Jev calls): engine clock qualification matched to a simulated-time, render-bound engine, an evaluator/controller isolation scan, a detection-envelope sweep (range × camera altitude/pitch × target aspect × ≥2 non-car detector-known classes × HFOV) whose predeclared rule picks among honest long-range options before L8 (long distance) may run, a **reference-ceiling sweep** that sets every rung's target-speed/bearing-rate envelope from measured reference-controller performance rather than assertion, and a **rig-geometry qualification** that picks the camera altitude/pitch and follow distance D from a feasible-band requirement. L1–L4 isolate track/range/follow difficulties, with the range/speed axis on moving-target rungs carried by a speed-hold menu (not the fixed-distance menu, which is kinematically unable to track a moving target) with rate-aware per-option consequences and an explicit `unknown` fallback. L5 (find when facing the wrong way) reuses F75's `sector-consequences` encoding, preceded by a static 70°-HFOV prerequisite probe (F75's oracle was only ever tested at 36°), and runs F75's proposed `new_never_inspected_deg` variant at development before any confirmation appearance. L6 (loss/reacquisition) requires both the fixed-observer and held-at-loss-pose counterfactuals; **L7 (lookalike identity) requires only the fixed-observer counterfactual** (corrected here — an earlier draft of this entry overstated L7's requirement to include both). L9 is the owner's hardest case: the `jev-scout`/`jev-spatial` search topologies rebuilt at car scale inside the Round 3 3D scene with obstacles resized relative to the chosen rig, run once per block (no separate development split, since the representation choices are already settled by L1–L8), with the F43-style pass rule (apparent-width band replaced by a range band — **this substitution is the design review's own recommendation, not the owner's instruction**, corrected here) required before any Jev-attributed verdict.
- **Second repair, 2026-09-21:** an independent review of this ladder (verdict: READY after listed repairs) found the follow-dynamics menu kinematically unreachable for a moving target, the proposed 5 m/−18° rig unverified and possibly too narrow a feasible band, every rung's gate parameters left as placeholders, a wall-paced clock gate applied to a render-bound engine with a wall-time estimate too low by roughly 5–10×, and several accuracy errors in this file's own additive annotations (including the lookalike-colour claim above). All are repaired in the current [`docs/jev-find-follow-ladder.md`](jev-find-follow-ladder.md), which now includes a frozen per-rung parameter table with no placeholders, a corrected clock/latency gate, a two-night (plus concurrency) wall-time budget derived from stated episode counts, and a "Repair verification" section recording what did and did not independently check out.
- **Advancement and selection rules, predeclared to avoid repeating known flaws:** a rung advances only when Jev reaches ≥85% of `reference`'s score, beats `passive` by a stated margin, and has zero harmful events on an untouched confirmation split; if `reference` itself fails, the fault is sensing/menu/timing, not Jev (F52's standing lesson). The selection rule is corrected for the two concrete failure modes F75 demonstrated: no payload fallback is used when no development arm clears the gate (report "no arm selected" instead of silently promoting the cheapest failing arm, as F75's S hypothesis did when it picked `current-only`'s 0% rate over `sector-consequences`' 80.6% near-miss purely on payload); and a payload tie-break between two arms that both cleared the development gate is never used without first checking they are not within noise of each other on a robustness margin (F75's R hypothesis picked `signed-error` over `after-range` on payload alone between two 100%-development arms, and `signed-error` then failed confirmation while `after-range` held 116/116).
- **Status:** planned before inference. No Jev call has been made for this plan. Outcomes, gate verdicts and any next discriminating test will be appended here after L0's gates and each rung's execution, following this file's own standing rule against tuning on held-out results.
