T2/T4/T5 did not earn additional complexity in these tests.** The original hypothesis ranking remains in [the durable top five](JEV-TOP-FIVE-TECHNIQUES.md); these results update the implementation priorities, not the historical ranking.

## What the logs show

**T1 separates useful routing from a repeatable freshness failure.** In every missing-marking confirmation instance, Jev requested the appropriate front/rear record and then made the supported decision: 8/8 responses. For example, [the rear-record request](../.runtime/experiments/jev-top-five-v1/requests/T1-confirmation-5-jev_selected-0.json) led to a matching code and a correct [retreat answer](../.runtime/experiments/jev-top-five-v1/responses/T1-confirmation-5-jev_selected-0--followup.json). Fixed depth appropriately deferred on those instances because it could not supply identity evidence. Its 8/16 score is supported *task resolution*, not 50% adherence to its available evidence: all 16 confirmation baseline decisions respected that evidence. The fixed-depth design has an 8/16 information ceiling; this does not establish an advantage over a deterministic missing-field router.

Conversely, all four stale-depth confirmation responses selected `keep`, then `maintain`. In [one exact request](../.runtime/experiments/jev-top-five-v1/requests/T1-confirmation-0-jev_selected-0.json), decision time was 73,000 ms and range acquisition was 71,000 ms, despite a 250 ms limit. The [selection](../.runtime/experiments/jev-top-five-v1/responses/T1-confirmation-0-jev_selected-0.json) retained that old range; the [follow-up](../.runtime/experiments/jev-top-five-v1/responses/T1-confirmation-0-jev_selected-0--followup.json) asserted maintain. This repeated in development. Treatment acquired eight additional records versus baseline's sixteen, but did so partly by incorrectly skipping necessary depth. Its confirmation median probe latency was 747 ms versus 208 ms, including the enforced inter-request wait between its two calls. Fixture sensor timestamps are stipulated; they do not include actual API delay and cannot establish live freshness.

**T3 protects relevant facts without blocking every changed observation.** Age-only applied eight unsupported effects and accepted 3/4 useful ones; whole-observation equality applied two unsupported effects and accepted only 1/4 useful ones; dependency validation applied zero unsupported effects and accepted 4/4 useful ones. The [traces](../.runtime/experiments/jev-top-five-v1/freshness.json) show why: a background change remains acceptable, a swapped target is rejected, and a forecast expiring at 0.35 seconds cannot support a maneuver whose braking interval ends at 0.36. Every arm checks Stop, owner, goal and command lifetime. These are injected logical endpoint/envelope cases, not physical collision tests or measured incident rates; authority changes during execution remain untested.

**T2 and T4 are ceiling results.** Both identity menus correctly distinguish supported matches, contradictions, twins, missing attributes and incomplete extraction, including the exact abstention reason. The extra adequacy question never disagreed with the target Choice. Both yaw menus use the same rendered-RGB-derived measurements and code-computed consequences. Copying each movement option eight times changed neither selected physical action nor hold/move. This does not rule out benefits with noisy real perception or harder mixed-action menus; it supplies no reason to add these questions to this baseline.

**T5's failure is authority interpretation, not job churn.** Both arms correctly continue quiet progress, preserve buffers through blockage/dropout, change target/goal configuration and restart failed workers. Each recovers 2/2 failed-worker responses; neither needlessly resets. Both choose continue on 2/2 expired-authority responses. In [the confirmation request](../.runtime/experiments/jev-top-five-v1/requests/T5-confirmation-6-0-explicit-lifecycle.json), `now=1100` and `expiresAt=1099`; [Jev still selects continue](../.runtime/experiments/jev-top-five-v1/responses/T5-confirmation-6-0-explicit-lifecycle.json). The executor rejects the operation and all subsequent reads. Zero forbidden effects therefore credits the code guard, not Jev. Detailed [family outcomes](../.runtime/experiments/jev-top-five-v1/log-inspection.json) distinguish new readings, recovery and existing completion; already-completed buffers are not new work.

## Next tests worth doing

1. **T3 integration:** inject target-generation changes, forecast expiry, Stop and owner revocation into an independently acquiring asynchronous loop, including changes during execution and braking. Measure useful effects retained and rejected stale effects separately. The current finite fixture justifies this next test.
2. **T1 diagnosis:** on fresh matched instances, change only raw timestamps versus code-computed age. Then test explicit validity as a separate intervention. Require useful acquisitions and zero unsupported commitments together; retain a deterministic missing-field router as a later comparator. T5's analogous expiry error supports a separate remaining-authority-time probe. These are hypotheses, not fixes already demonstrated.
3. **Defer T2/T4/T5 expansion** until harder evidence exposes a failure of the simpler baseline. Keep the previously tested computed-bearing representation; these static yaw probes do not improve on the earlier timed-framing result.

T1/T2/T5 use stipulated acquired records or generated job readings. T4 uses fresh rendered RGB, a color detector and calibrated projection, with stationary-target assumptions. T3 uses a bounded logical dispatcher. None tests real car recognition, stereo accuracy, MAVLink transport, sustained following or hardware. All proposed larger tests remain unrun.
