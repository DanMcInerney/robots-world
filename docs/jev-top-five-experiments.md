# Isolated tests of the five Jev techniques

19 September 2026. Prospective plan; no results at authoring. The user requested these experiments and real execution after the [ranked techniques](JEV-TOP-FIVE-TECHNIQUES.md) and [research audit](JEV-ECOSYSTEM-TECHNIQUES-AUDIT.md). This authorizes the bounded hosted-Jev component campaign below; no hardware is involved.

The question is whether each technique earns a further integrated trial. Keep the five interventions separate. Use Jev 1.13.0 and the existing validated transport. Archive exact requests/responses, all failures, timing, source versions and measured/model-selected outcomes under `.runtime/experiments/jev-top-five-v1/`. No prompt or threshold changes after the first real response. Confirmation cases are declared before inference and run after the development ledger is sealed; they are fresh instances of the same narrow task families, not proof of generalization to new environments.

| ID | Isolated comparison | Measurements and advance rule |
| --- | --- | --- |
| T1 | Fixed depth acquisition versus Jev choosing depth, front/rear appearance evidence or no further acquisition. Both receive the same initial stipulated acquired records, one additional evidence-operation allowance, and the same final decision task. | Correct final decisions supported by the acquired evidence, false commitments, useful observation choices and additional request latency. Advance if confirmation treatment has at least 14/16 correct, improves by at least 4/16 over fixed acquisition, and has no more false commitments. This tests evidence selection over declared records, not image recognition or physical viewpoint feasibility. |
| T2 | A single candidate Choice already containing none/ambiguous/incomplete options versus that exact Choice plus an independent categorical adequacy gate. The gate may veto but cannot pick a different car. | False identity commitments, supported unique matches retained, correct abstention and gate/choice disagreement. Advance only if it removes at least two false commitments on confirmation, creates none, retains at least 7/8 supported matches, and loses no more than one correct supported match versus baseline. A tie at excellent performance means the extra question has not earned its cost. |
| T3 | Same delayed command and latest observations; age-only, whole-observation and action-dependency validation. Stop, goal version, ownership and command expiry are mandatory in every arm. | Actual effects, independently assessed invalid effects, useful effects falsely blocked and explicit rejection reasons. Advance the mechanism if dependency checks allow every declared valid effect, reject every invalid effect, improve invalid-effect rejection over age-only and reduce unnecessary rejection versus whole-observation equality. This is deterministic lifecycle qualification, not measured model or physical-safety performance. |
| T4 | Flat complete yaw menu versus hold/move plus an independently conditional movement Choice. Cross one versus eight identical copies of each moving action. Hold remains available; physical effects and evidence are identical. | Exact acceptable physical decisions, hold/move flips and physical-action flips under duplication, direction errors and useless motion while already framed. Advance only if the conditional arm improves confirmation correctness by at least four responses or reduces duplication-induced mode flips by at least two matched pairs. Either route also requires no overall correctness regression, at least 14/16 correct required turns with no loss versus baseline, and no increased inappropriate movement. Otherwise retain the simpler flat menu. |
| T5 | Same persistent sampling-job state, same executable actions and effects; concrete action descriptions versus explicit continue/change/restart/finish wording. No executor is secretly made worse in one arm. | Correct operation, preserved progress, unnecessary resets, useful restart/change after failure, and expired-authority effects. Advance only if confirmation reaches at least 14/16 correct and gains at least 3/16 correct without more inappropriate resets or authority violations. A deterministic executor demonstration alone does not establish better Jev choices. |

T1, T2 and T5 use small analytic acquired-record/job fixtures with their evidence stipulated and explicitly labeled. They contain no hidden oracle or future outcome in Jev state. T4 uses fresh synthetic RGB frames passed through the existing color detector and calibrated projection; truth supplies only rendered pixels and offline evaluation. It is a single-object yaw/representation test with fixed translation, not metric following or semantic vehicle identity. T3 injects faults around an actual bounded test dispatcher and records whether effects occurred.

Planned size: eight units per split for T1/T2/T5, two identical repetitions per unit and two arms. T1 has at most 96 calls including adaptive follow-ups; T2 and T5 each have 64. T4 uses eight frames per split, two repetitions, two duplication levels and two arms: 128 calls. Total ceiling for the fixed design is 352 requests; an operational cap of 400 requests and 2,000,000 accounted input tokens applies, including conservative reserves for missing usage. Start at most two requests per second, serially, with a ten-second transport deadline. No automatic retries or replacement of failed requests. An uncertain call halts dependent inference and remains in the ledger.

Randomize/interleave arm and unit order reproducibly within each split and repetition. Repeat IDs remain distinct even when payloads match. Questions within one request cannot read sibling answers: conditional wording and code's branch consumption must be explicit. Any sequential acquisition consumes the additional call/time it actually uses. No method is selected using confirmation data.

Implementation checks precede inference: fixture integrity, identical facts/actions across arms, correct abstention and useful-positive cases, exact candidate mappings, cancellation/expiry, guarded side effects, and deterministic analysis of synthetic replies. Run repository tests, typecheck and build.
