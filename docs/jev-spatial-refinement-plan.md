# Spatial refinement: simpler state, explicit geometry and dated evidence

19 September 2026. This is the next bounded campaign after F45–F54. It seeks the simplest representation that survives fresh checks; it cannot prove a universally ideal format. The accumulating lessons remain in [design-failures.md](design-failures.md). Earlier results and source freezes remain unchanged.

## Questions and controls

| Study | Exact comparison | Planned API requests | What it can establish |
|---|---|---|---|
| Geometry | Raw / current relations / computed after-bearing / computed after-relations × action-only / action plus seven independent conditional heads; 32 new states, two identical repeats | 512 | Whether declared computation, labels or extra heads change signed-turn interpretation |
| Temporal evidence | Raw / computed coordinates × mixed / explicit observation-time and frame-time schema; 32 new states, two identical repeats | 256 | Whether an old observation remains old after coordinate transformation; epoch and hypothesis semantics |
| Own-history replay | Receipts / linked-eight / diary-eight / lossless tuple-eight / linked-two / byte-matched neutral padding; 24 recorded states, three identical repeats | 432 | Layout, amount-of-history and unrelated-context sensitivity at identical snapshots; observed repeat variability |
| Stereo | SGBM block5 / SGBM block3 / StereoBM block9 on the same 56 fresh pairs | 0 | Hazard preservation versus unsupported/unknown output and useful coverage |

There are **1,200 fixed requests**. Geometry and temporal states each have eight mirrored units per development and confirmation split; repeats and mirrors are not independent environments. All templates, cases, hypotheses, question meanings and scoring keys are frozen before inference. Confirmation geometry differs from development but shares the diagnostic generator; no broad structural transfer claim.

History snapshots come from the prior linked-history arm, every pattern and mirror, at fixed request ordinals 4, 12 and 28. Selection is by those ordinals, not response correctness, confidence or later success. They are regression data, not a new holdout. Three full-history layouts retain identical atomic facts. Two-episode history removes information; receipts and padding remove history while preserving the original two receipts. Padding matches complete UTF-8 request bytes to linked-eight, not model tokens. Repeat requests are byte-identical despite distinct dispatch IDs.

History replay retains the action question, adding only a shared archived-snapshot notice. Its evaluator reprojects current measured box edges under a **stationary target and fully settled command assumption**. Outside the band it counts unclipped movement closer to center; inside the band it counts preserving framing. Ambiguous, absent or clipped current detections have no action key. This is a static progress proxy, not realized future success. All answers, including unscorable states, enter repeat-variability analysis. No candidate is promoted on these known failure snapshots alone.

Geometry cases explicitly stipulate the stationary/full-execution assumption. Every action gets the same consequence computation; no action is removed, ranked or selected by code. The raw arm keeps arithmetic in Jev; computed arms are declared assistance. Expected answers and quality metrics remain outside model state. Temporal questions use the same explicit evidence-kind vocabulary in all arms so the comparison does not repeat F48's missing-category confound.

## Order, selection and stopping rules

1. Verify generators, same-fact/repeat invariants, legal Choice requests, mirrors, boundary behavior and evidence provenance. Independently review the stable joined candidate before API dispatch; apply at most one coordinated repair/check pass at that gate.
2. Run development geometry/temporal plus all history regression cases: 816 requests. The dispatcher starts no more than two requests per second, uses the existing pinned `jev-1.13.0`, saves exact requests/responses and does not retry unresolved calls.
3. Before confirmation calls, record a geometry candidate based on development action accuracy. Among arms within one correct answer of the highest action score, choose action-only if eligible, then the lowest average serialized request bytes, then lexical arm name for a deterministic tie. This selects a compact candidate, not an optimum policy. Record the temporal candidate separately using critical assertions first, then factual accuracy, then payload size and lexical name. Critical assertions count each unsupported current-location/current-source assertion, each asserted spatial join across an invalid epoch (including accepting its motion hypothesis), and each substitution of frame/decision time for acquisition time. A response can have multiple critical assertions; denominators and categories remain visible. No prompt or fixture editing follows these selections.
4. Run the remaining 384 confirmation requests and report every arm, the preselected candidates, per-question denominators and repeat variability. Geometry's provisional gate is at least 95% optimal-action accuracy and zero wrong-direction or unnecessary out-of-view choices on confirmation. Temporal's gate is zero false-current/invalid-epoch assertions and at least 90% factual accuracy. Passing finite component gates is not flight qualification.
5. If a geometry candidate passes, qualify its measured-state adapter offline, review that stable integration, and compare it against the common receipt baseline on at most sixteen fresh 20-second yaw episodes (two arms × four patterns × two mirrors). Otherwise, record the failed gate and build the next discriminating fixtures without claiming a winning controller. Fresh yaw outcomes cannot retroactively change the component selection. At this stage the target must initially be observed; full search/navigation remains outside the yaw component.

This campaign's ceilings are 3,000 requests and 25 million input tokens, including uncertain reservations. Added to the prior 3,383 requests and 19,216,824 tokens, these remain within the previously established 25,000-request / 250-million-token ceiling. No hardware, full missions or new inference service is authorized by this plan. Another unresolved inference or invalid timed episode stops dependent dispatch for diagnosis; no automatic replay or silent replacement.

Raw evidence is under `.runtime/experiments/jev-spatial-refinement-v1/`. Source and cases are frozen before execution. Lessons will distinguish a model error, sensor error, ambiguous specification and experiment-infrastructure error; each entry will name the next falsifiable test. Keep positive exceptions, unknown coverage and failed attempts visible.

## Research basis

The refreshed [Jev limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13) recommend explicit criteria, code-owned arithmetic/time comparisons, fewer inference steps and relevant state. The [Choice contract](https://docs.typesafe.ai/primitives/choice) makes questions independent, hides question IDs from the model, and exposes option names/descriptions. These are reasons to test the proposed representations, not guarantees of performance.

The production OpenCV APIs offer distinct [StereoSGBM](https://docs.opencv.org/4.x/d2/d85/classcv_1_1StereoSGBM.html) and [StereoBM](https://docs.opencv.org/4.x/d9/dba/classcv_1_1StereoBM.html) matchers. Smaller support can preserve detail while changing noise and coverage. The stereo study freezes parameters before its challenge evaluation and grades all hazard pixels, not just surviving estimates. It remains an offline image benchmark rather than a physical-camera comparison.
